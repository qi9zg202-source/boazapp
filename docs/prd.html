Project PRD · Decision Header

Boaz Health：本机可信记录，受控的私人云同步

为使用 iPhone 与 Apple Watch 的本人提供可核对的睡眠、活动和体征记录；先在手机安全保存可读取的 Apple Health 数据，再由本人单独决定是否连接私人 Tokyo 接收服务。本文用于判断首个受控版本能否进入真机和 Tokyo 验收，不是上线证明，也不提供诊断。

HealthKit 只读 本机 SQLite 权威 上传需单独同意 AI-NATIVE GATE: INTERCEPT
当前决策：继续封闭真实上传。源码正在收口手机 SQLite、Tokyo 健康账本、独立控制账本和可重建指标投影，但缺少签名真机、Apple Watch、私人 HTTPS、独立加密恢复域、原生 VictoriaMetrics 身份、隔离恢复及回滚的现时验收证据。77 个测试用例是验收要求，不是通过回执；2026-09-18 验收报告与 历史证据存在且保持不可变，但不会自动证明 2026-09-19 的组合工作树。

03 Dynamic Hedge Record

审查视角裁决记录
0 Boundary LockHealthKit 可读样本是输入；手机 SQLite 与 Tokyo SQLite 分别是本地/云记录权威；VictoriaMetrics 仅为派生数值投影。上传、删除和部署是高影响动作，必须显式同意、可审计、可恢复。
A-System Blueprint保留稳定样本 ID、revision、anchor、不可变批次字节、回执、权限/同意状态；Tokyo 将健康 payload 与撤销/擦除/恢复事实分置于健康库和独立控制库，以“控制意图先提交、健康账本后收敛”避免伪造跨 SQLite 原子事务。风险是恢复链和部署门禁的验收成本较高。
B-Minimal Patch首版只聚焦本机阅读、单一手动同步、私网收件箱和状态审计；不加 LLM、Meilisearch、Qdrant、Neo4j、GraphRAG 或 LangGraph。风险是历史规模、跨设备与运营测量尚未覆盖。
A-vs-B Hedge极简路径不能删掉隐私、幂等、删除、恢复和真机门禁；完整架构也不应为了“AI 原生”引入无指标收益的额外服务。
0 Final Arbitration by Palantir Chief Ontology Arbiter此处仅借用对象/证据/动作的审查方法，不代表使用 Palantir 产品。优先级为隐私与安全 → 当前证据 → 数据身份 → 恢复 → 体验/速度。
Optimal Solution / Verification Hook保留现有确定性双账本架构；先完成真机与封闭 Tokyo 验收，再申请真实上传。用 用例矩阵和逐条可核对的执行回执判定 PASS/FAIL/BLOCKED，不以编译、演示图或 HTTP 2xx 代替。

06 对象、状态与血缘合同

对象 / 稳定身份关系与状态权威与 owner
HealthEvent：HealthKit UUID + 类型；derived event 另有版本upsert/delete、revision；属于来源和可选 workoutApple Health 可读数据为输入，手机 health_events 为保存权威；本人控制授权
QueryAnchor：按类型/关联 workout 键与同页事件在一笔本地事务提交手机 query_anchors；采集器维护
UploadBatch：batch_id + 不可变请求体/哈希pending → cloud_saved → metrics_current；失败重试手机 upload_batches；上传者维护
Tokyo Event / Receipt：device_id + event_id / batch_id健康库 BZHR v2：修订、墓碑、commit_sequence、projection generation/versionTokyo 健康 SQLite；服务运维者维护
ControlEvent / control store ID控制库 BZHC v1：token tombstone、擦除意图、指标擦除与恢复事实；hash 链 + head + mirrorTokyo 独立控制 SQLite；不保存健康 payload、明文 token 或明文 erasure secret
Metric job / series由已提交事件派生，可重建；receipt 绑定 generation/mapping version；同毫秒点位可能合并原生 VictoriaMetrics 仅为投影；generation 漂移使旧指标回执降级，健康库仍是记录权威
Erasure：device_id + erasure_id控制意图先封禁旧 token，再收敛健康/指标/受管备份；合法 complete 后手机幂等轮换 device_id控制账本保存不可回滚事实；新身份必须重新配对和重新同意上传

所有关键状态必须带时间、来源和可回读证据；“无可读数据”“查询失败”“未授权”“未投影”不能合并为零值或成功。已解决的批注只是本文的本机审阅记录，不是产品验收回执。

09 数据、逻辑与集成边界

确定性基线：HealthKit 查询、SQLite 事务、批次哈希、规则校验、状态机与数值单位转换可以直接解决首版任务。Meilisearch、Qdrant、Neo4j、GraphRAG、LangGraph 和大模型目前均不采用：没有可证明的召回、决策、速度或成本收益；若未来加入，必须先给出新任务、权威数据源、错误模式、预算和验收指标。无付费模型调用。

边界契约失败模式 / 验收
Apple Health → iPhone只读取 allowlist；样本按最多 500 条分页，anchor 与页同事务；活动全量/近七天扫描策略见源码撤权、空数据、异常 anchor、删除、跨时区和超大历史均要测；不能以空结果证明完整
iPhone → Tokyo仅在配对和独立同意后经私人 Tailscale HTTPS；Serve 目标为 loopback 127.0.0.1:8787；每批至多 200 revision / 128 KiB端点校验器拒绝 HTTP、公开地址、凭据/query/fragment 和重定向；同 batch ID 不同字节失败关闭
Tokyo control → health SQLite鉴权先查控制 tombstone；撤销/擦除意图先落控制库，健康库通过启动/运行 reconciliation 幂等收敛不宣称跨库原子事务；控制 DB/head/mirror 或 store ID 分叉时拒绝启动/继续
Tokyo SQLite → VictoriaMetrics仅投影已提交、单位可校验的数值；指标名 boaz_health_v1_*；回执绑定当前 generation/mapping versionHTTP 2xx 不等于原生身份或持久化；label hashing 尚未实现，当前不得扩展任意 metadata 标签
加密 / 备份 / 删除当前运行时挂载验证器只识别 Linux dm-crypt；控制库必须在不同恢复域；健康快照 manifest 需绑定 control headprovider-managed encryption 尚未由代码验证；staging restore、离机 expected head 和东京灾难恢复仍是门禁

仿真 / M&V / ROI：无 CFD 或医学模型；工程合成样本只用于事务、数值和恢复验收，不能代表真实健康准确率。成功指标为记录集合一致、错误状态诚实、恢复完成、手机资源和运维成本实测；基线/目标数字待真机和 Tokyo 测量后冻结。

11 风险、演进与未决问题
