## Decision and actual change

**AI-NATIVE GATE: INTERCEPT.** A synthetic counterexample demonstrates that the custodian's internally consistent v2 history, seal and head can all be rolled back together and still pass its local verifier. A separately owned monotonic witness is therefore required to claim freshness. No approved independent receiver/custodian/witness host, encrypted domains, fixed identities, performance budgets or authorization were established in this run. No production witness was fabricated from a local file, and production `serve` remains closed.

Three locally proven false-success/freeze paths were repaired without changing public HTTP shapes: (1) a control CAS response alone no longer removes its durable intent; a separate exact custody read must confirm persistence; (2) a health-ledger erasure `complete` row cannot be returned unless settled control/custody facts and metrics/backup verification timestamps match; (3) the projection worker now holds the existing health-operation lock before erasure convergence or VM work, so a backup freeze prevents that worker mutation. The worker may now contend with ingest and backup for the duration of a projection pass; no Linux latency claim follows from local tests.

The minimal proposed witness would store only an independently owned monotonic revision, store ID and digest of the entire custody-state tuple, binding the stable operation ID and intent digest to the original reserve/CAS. Both custody and witness must read back the same successor before external success; disagreement retains the original intent and stops new authoritative writes. This remains **design, not code or host acceptance**, pending owner, authenticated identity/rotation, encryption, outage policy and cost target. A constant second receiver, distributed database, queue or AI orchestrator would add sensitive state without proving freshness.
